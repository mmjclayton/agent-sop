### HIGH

- **`scripts/validate-state-transitions.sh:164` is the same P73 bug, unguarded, and the audit claim in `docs/build-plans/phase-0-foundation.md:67` is wrong.** `worktree_count=$(git worktree list 2>/dev/null | wc -l | tr -d '[:space:]')` — `git worktree list` exits 128 outside a git repository, `2>/dev/null` hides the message, `pipefail` carries the 128 past `wc` and `tr`, and `errexit` kills the script. Reproduced: in a non-git directory, `bash scripts/validate-state-transitions.sh --check-drift` exits **128 with empty stdout and empty stderr**. Setting `CLAUDE_AGENT_ID=solo` bypasses line 164 and the same invocation exits 0 with `check-drift: no project_resume file found — skipping`. That is exactly the signature the P73 comment at `scripts/validate-state-transitions.sh:502-508` describes, at a site the batch log says was audited. The script clearly *intends* to degrade gracefully outside git — `scripts/validate-state-transitions.sh:226-238` has a "no default branch — skipping" path, and check D1 in `docs/sop/compliance-checklist.md:271` asserts `--check-drift` "works when invoked" — and line 164 defeats that before either can run. The batch log also states "Audited all 8 command-substitution sites"; `grep -cE '=\$\(' scripts/validate-state-transitions.sh` returns 28, of which 24 are non-arithmetic assignments and 17 contain a pipe. **Fix:** `worktree_count=$( { git worktree list 2>/dev/null || true; } | wc -l | tr -d '[:space:]')` and `[ -z "$worktree_count" ] && worktree_count=0`. Also guard `head_sha=$(git rev-parse HEAD 2>/dev/null)` at `scripts/validate-state-transitions.sh:243` (reachable only if `git merge-base` at :239 somehow succeeds without HEAD, but it is the same shape). Correct the "8 sites" figure in the batch log to what was actually audited.

- **Check T1's own grep-verifiable criterion fails on the file it gates.** `docs/sop/compliance-checklist.md:269` states: "Grep-verifiable by pattern `cannot be fixed quickly` returning nothing in `.claude/commands/update-sop.md`." `grep -n 'cannot be fixed quickly' .claude/commands/update-sop.md` returns a match at `.claude/commands/update-sop.md:186` — the historical-explanation paragraph added by this same diff quotes the old wording verbatim. - **`docs/benchmark/run-multi-round.sh:145` silently pools rounds and double-counts runs.** The awk key is `key=$2 SUBSEP $3` — task and arm only. Column 1 (`round`) and column 4 (`run`) are required by the `NF < 5` guard at `:144` and then never used. Reproduced: a TSV holding round 5 (sop=10/10/10, nosop=90/90/90) and round 6 (sop=90/90/90, nosop=10/10/10) — two rounds each showing an ±80-point effect in opposite directions — aggregates to `5 sop 6 50.00`, `5 nosop 6 50.00`, delta `+0.00`, annotated `RANGES OVERLAP — not separable at this k`. Two decisive and contradictory results are reported as no effect and no separability. The script's own instruction at `:106` tells operators to record `round<TAB>task<TAB>cond<TAB>run<TAB>score`, so accumulating rounds in one file is the expected usage, and rounds are pinned to different base commits and different SOP versions — the exact cross-version contamination the frozen-lite-subset rule at `docs/benchmark/README.md:48` exists to prevent. Separately, because `run` is ignored, pasting the same row three times yields `k=3` (verified), which silently satisfies the README's k>=3 minimum from one sample; k is the quantity the whole P68/P72 chain gates on. **Fix:** key on `$1 SUBSEP $2 SUBSEP $3` and print the round in the output table, or reject input containing more than one distinct `$1` with a non-zero exit. Deduplicate on `($1,$2,$3,$4)` and warn on collision rather than counting the row twice.

### MEDIUM

- **`scripts/validate-state-transitions.sh:552` — `head -1` lets one line's skip token exempt a P-number that declared nothing.** `batch_line=$( { grep -E "\b${p}\b" "$batch_match" || true; } | head -1)` picks the first line naming the P-number, not the line that *is* that item's entry. Reproduced with a two-line Batch Log: `- 2026-07-26 P299 review skipped: docs-only (prep for P300)` followed by `- 2026-07-26 P300 real code, no review, no skip` — a `[Feature]` P300 with a real code diff ships at exit 0. Same result on a single line: `- 2026-07-26 P299 review skipped: docs-only. Also unblocks P300 which shipped with real code.` The `head -1` selection is pre-existing (the identical shadowing works against `main` using a `docs/reviews/` path on an earlier line, verified), but P66 widens it materially: a review path is a rare artifact, whereas `review skipped: docs-only` is a phrase that will now appear in routine batch summaries, and batch summary lines routinely name several P-numbers at once — `docs/build-plans/phase-0-foundation.md:67` names five. One token on a multi-P line exempts every item on it. **Fix:** require the token and the P-number to co-occur on a line that also looks like that item's own entry — e.g. anchor on `\*\*${p}\*\*|^[-*] .*\b${p}\b` and require the match to be the *only* P-number-bearing candidate, or fail closed when more than one line matches and none is unambiguous.

- **`scripts/validate-state-transitions.sh:553` — the skip token has no trailing boundary, so "free text is not accepted" is overstated.** `skip_re='review skipped: *(docs-only|test-only|dep-bump|below-threshold)'`. Verified passing: `review skipped: docs-onlyish-i-made-this-up` and `review skipped: dep-bumpkin`. An agent cannot invent a *new* reason word, but it can glue arbitrary self-judgement onto an enumerated prefix — `review skipped: below-threshold-ish-i-eyeballed-it` passes. `.claude/commands/update-sop.md:169` claims "A free-text reason is not accepted — the escape is bounded, not self-judged", and `docs/build-plans/phase-0-foundation.md:67` claims "both boundaries have fixtures"; only the two coarse boundaries are fixtured, not this one. **Fix:** `skip_re='review skipped:[[:space:]]*(docs-only|test-only|dep-bump|below-threshold)([^A-Za-z0-9_-]|$)'` and add a third fixture for the suffix case.

- **`docs/benchmark/run-multi-round.sh:157-164` — `aggregate` exits 0 when it produced no comparison at all.** With arm labels `sop`/`no-sop` (one hyphen), the delta loop's `if (!((t,"sop") in M) || !((t,"nosop") in M)) continue` fires for every task; the tool prints the header `delta on medians (sop - nosop):`, nothing underneath, and returns 0. Same for a space-separated file (a likely mistake given the README renders the format as prose `round<TAB>task<TAB>cond<TAB>run<TAB>score`): "warning: 2 malformed row(s) skipped", an empty table, an empty delta section, exit 0. A run that computed nothing reports success. This is the shape P73 just fixed in the validator — the branch's own principle at `docs/benchmark/state-transition-fixtures/run-tests.sh:95` is "when a check's product is a diagnostic message, assert on the message." **Fix:** track a printed-delta counter in `END` and `exit 1` with `ERROR: no task had both arms — check the cond column (expected exactly 'sop' and 'nosop')` when it is zero; also exit non-zero when `bad` equals the total non-comment row count.

- **`docs/benchmark/run-multi-round.sh:149,158` — `for (t in tasks)` output order is unspecified and already scrambles.** Verified on macOS awk with the full eight-task set: rows emit 2,3,4,5,6,7,8 and then **1 last**, in both the summary table and the delta block.
