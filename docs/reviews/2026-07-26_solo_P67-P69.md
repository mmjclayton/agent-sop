- [`docs/sop/compliance-checklist.md:257`, `.claude/agents/sop-checker.md:149-152`] **S7's git command is inert against merged history — it can never FAIL.** The specified range is `<merge-base>..<ship-commit>`. A `[SHIPPED]` item's ship commit is by definition an ancestor of the default branch, so `git merge-base main <ship-commit>` returns the ship commit itself and the range is empty. I ran the literal command against this repo's last three ship commits: `4ad01f8`, `2aad84c`, `116be62` — merge-base resolved to the commit itself in all three, and each produced zero output, i.e. an unconditional PASS. Only the unmerged working HEAD `842f835` produced output (`.claude/agents/sop-checker.md`), and unmerged HEADs are not `[SHIPPED]` items. The check is structurally incapable of detecting the tamper it was written to detect. — Fix: for squash-merged ships use `git diff --name-only <ship-commit>^..<ship-commit>`; for true merge commits use `<merge-commit>^1..<merge-commit>`; state which convention the project uses rather than reusing the `<merge-base>..` phrasing copied from R1 at `compliance-checklist.md:267`, where it has the same defect.
