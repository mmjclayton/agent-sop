## Findings

- **[HIGH]** `.claude/commands/update-sop.md:309` — Step 4 skip predicate uses `&&` where the prose at line 306 specifies `OR`. With `&&`, the condition is true only when SESSION_RANGE is empty AND no `[SHIPPED]` tag was added. A parallel agent on a feature branch has non-empty SESSION_RANGE, so the first clause is always false and the whole predicate is dead for parallel agents. Fix: change `&&` to `||` so the predicate fires whenever either clause holds (matching the prose intent: skip when the range is empty OR when nothing shipped).

- **[MEDIUM]** `docs/guides/multi-agent-parallel-sessions.md:359-365` — `exit 1` inside a piped `while read` loop exits only the subshell. The §7 snippet is documented as a hard gate; in bash a pipe forces the right-hand side into a subshell, so `exit 1` does not stop the outer script — the calling shell continues. Fix: collect the dirty result outside the subshell (temp flag file) or rewrite using process substitution `while read ... < <(awk ...)`. Note: the same construct exists in `.claude/commands/restart-sop.md:27-33` but is advisory-only there, so the subshell behaviour is benign.

- **[MEDIUM]** `.claude/commands/restart-sop.md:27`, `docs/guides/multi-agent-parallel-sessions.md:359` — `awk '/^worktree /{print $2}'` truncates worktree paths containing spaces. `awk`'s default whitespace splitter drops everything after the first space; the subsequent `git -C "$wt" status` runs against a non-existent path, returns empty, and the dirty worktree is silently reported clean. Fix: replace `print $2` with `sub(/^worktree /, ""); print` so the full remainder is printed verbatim.

- **[LOW]** `.claude/commands/update-sop.md:306` — prose names the skip-predicate command as `git diff --name-only HEAD..HEAD`, which is a null range and always empty. The parenthetical and the code below use the correct working-tree-vs-HEAD form. Fix: replace the prose form with `git diff HEAD -- Backlog.md` to match the code.
