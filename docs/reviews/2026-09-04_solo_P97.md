## Findings

- `scripts/hooks/sop-push-gate.sh:32` — **HIGH.** Detection regex required `git`/`gh` to follow a separator or whitespace, so `bash -c 'git push origin main'`, `sh -c "gh pr create"` and `eval "git push"` passed the gate silently with no `bypass.log` entry, defeating the one hook that can refuse. No fixture covered a wrapped invocation. **Fixed:** new `sop_is_push_command` in `sop-lib.sh` recurses into the quoted body of `bash|sh|zsh|dash|ksh -c` and `eval`, then strips remaining quoted strings and matches the residue; the bare pattern also accepts a closing backtick, `;`, `&`, `|` or `)` after the verb. Fixtures `push-bash-c-wrapper-refused`, `push-sh-c-double-quoted-refused`, `push-eval-wrapper-refused`, `push-backtick-refused`.
- `scripts/hooks/sop-push-gate.sh:32` — **MEDIUM.** `echo "remember to run git push after this"` matched the same regex and hit the refuse path for a command that never touches the remote, against the "silent unless a deterministic fact holds" rule in `sop-lib.sh`. **Fixed** by the same change: text inside quoted arguments is stripped before matching. Fixtures `push-verb-in-quoted-prose-silent`, `push-verb-in-commit-message-silent`.
- `scripts/install-hooks.sh:69` (`write_settings`) — **MEDIUM.** `mv "$tmp" "$SETTINGS"` over a symlinked settings.json replaced the link with a plain file, leaving a dotfiles-managed source stale so a later sync would silently drop the registered hooks. **Fixed:** `resolve_settings_target` follows the link chain (up to 10 hops, relative links resolved against the link's directory); backup and write both target the real file. Fixture `installer-preserves-symlinked-settings`.
- `scripts/hooks/sop-lib.sh:140` (`sop_tracker_dirty`) — **LOW.** `awk '{print $NF}'` on porcelain output truncated paths containing spaces and rename lines to their last token; gating unaffected, the human-readable list wrong. **Fixed:** `sed` strips the three status columns and takes the post-arrow path; `--untracked-files=all` so an untracked file inside an otherwise-empty tracker directory is named rather than the directory. Fixture `stop-dirty-path-with-space-intact`.
- `scripts/install-hooks.sh:81` (uninstall filter) — **LOW.** `test("/sop-(session-context|stop-drift|push-gate)\\.sh")` removed any hook whose command path ended in one of those filenames, from any directory, so a user's unrelated `~/other-tool/sop-stop-drift.sh` would go with ours. **Fixed:** filter anchored to `startswith("bash \"<dest>/")`. Fixture extends `installer-uninstall-removes-only-ours` with a look-alike hook that must survive.
